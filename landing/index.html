The difference

Two different questions

Request filtering tries to stop the attempt. Vorynex assumes one will get through and limits the consequence.

A WAF asks

Is this HTTP request malicious?

Vorynex asks

Even if the code runs, what should this workload be allowed to do?

Adoption without fear

Observe. Protect. Lockdown.

Start with zero enforcement, then tighten only as confidence is earned.

01

Observe

Run with zero enforcement. Vorynex records what it would have blocked, so nothing breaks in production.

no enforcement
02

Protect

Block only high-confidence danger: shells, secret files, cloud metadata, arbitrary egress.

high-confidence only
03

Lockdown

A strict generated allowlist. Only known capabilities work. For hardened, stable workloads.

allowlist only

Enforcement

Two layers, one policy

Spawn-time containment where you can restart; live enforcement where you cannot.

Spawn-time

Landlock · unprivileged · works inside Docker

  • ✓Read/write limited to granted paths
  • ✓Exec limited to the workload's own runtime
  • ✓All outbound TCP denied unless allowlisted
  • ✓Applied at launch; inherited by every child

Live

eBPF-LSM · cgroups v2 · nftables

  • ✓Enforce on a workload that is already running
  • ✓File-granular exec and path control
  • ✓No restart required
  • ✓Degrades honestly when the kernel cannot support it

Emergency Shield

A CVE drops. Contain it before you patch.

Vorynex maps exploited vulnerabilities to the workloads that run them, drafts containment, and proves it before it enforces.

The pipeline
new CVE→ affected workloads→ candidate containment→ deterministic validation→ observe→ protect

Sources include CISA KEV, NVD, GitHub Security Advisories, OSV, and vendor advisories. AI may summarize and draft a rule; it never pushes an untested block to production.

Mitigation is not a patch. Emergency Shield buys time. It does not replace fixing the vulnerability.
Example

CVE-2026-XXXX · KEV · CVSS 9.8

  • ✓2 affected workloads identified
  • ✓shell execution from web worker denied
  • ✓cloud metadata access denied
  • ✓validated against recorded traffic
  • !egress restriction needs review

Local-first

The cloud is optional. Protection isn't.

Enforcement runs on your machine. If the control plane is unreachable, policies keep protecting the application.

Contain compromise. Not just attempts.

Vorynex reduces what an attacker can do after a vulnerability is exploited. It is not a WAF, a scanner, or a guarantee. It is runtime least privilege, made operable.
