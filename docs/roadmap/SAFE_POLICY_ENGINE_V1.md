# Safe Policy Engine v1: status

Done: root cause; capability gate for directory-granular exec; `vorynex verify` with coverage states; safe fixture + corpus; demo with control arm; CI job (unrun on GitHub).

Not done (honest list):

1. **Partly done:** `run --watch` gives bounded post-activation verification. **Supervisor crash is now handled for `run`** (pending marker, Pdeathsig, recovery on next start; demo 6c). Still open: multi-level rollback (single snapshot), watch is not continuous, `protect` paths don't use the pending marker, no independent watchdog.
2. Tier 0 still emits no denial events of its own. **Partly done:** `vorynex verify --trace` captures EACCES/EPERM syscalls via strace and names the refused call (e.g. `execve .../ping x20`). These are candidates, not proof (cgroup files also give EACCES). Still open: `observe`/`trace` integration and Landlock audit on newer kernels. **New finding from the trace:** `/etc/resolv.conf` is denied under the default policy (likely a symlink outside the readable runtime dirs); the `dns` workflow only resolves `localhost`, so it misses it. Add a real-resolver workflow next.
3. **Done.** `engine/policygen/adversarial_test.go` replays an attacker active in every recording session, under both the `observe`/`protect` thresholds and the defaults. It found two holes, both fixed: (a) `curl`, `nc`, `python3` and a renamed shell copy were promoted into `exec.allow`; (b) a hostname destination such as an exfil domain was promoted into `network.allow`. Now only the workload's own binary (first exec of a session) can be promoted; every other executable and every observed network destination is a `review` item that never becomes a grant. `observe` and `policy generate` list them, and the operator adds legitimate ones to the policy by hand. Cost: learned egress hosts no longer appear automatically. Tier 0 denies all outbound TCP regardless (no host allowlisting yet), so this removes no working enforcement today.
4. **Mostly done.** Corpus is now 14 checks / 380 requests: adds real-resolver read, worker subprocess (the runtime, argv, no shell), 200 concurrent requests, graceful shutdown (SIGTERM exits 0) and cold restart (`verify --lifecycle`). **It found a real false positive:** on systemd-resolved hosts `/etc/resolv.conf` is a symlink into `/run`, so any app doing DNS got EACCES. Fixed in `spawntime` by granting read on just that file (and `/etc/hosts`, `/etc/nsswitch.conf`), not `/run`. Still open: outbound API and database calls, retries, uploads of realistic size, scheduled tasks, dependency updates; no Express/Next.js fixtures (Express is not installed here, and none was claimed supported). TCP DNS fallback is still denied by the TCP-connect rule.
5. Exception schema with approver/reason; approval workflow; `conflicts`/`rollback` CLI verbs.
6. Tier 1, Docker integration, performance of memory/CPU/startup: not measured.
7. **Partly done:** AppArmor, SPO, Tetragon and Falco claims that matter to design were checked against source (see COMPETITIVE_POLICY_ENGINEERING.md). Cilium, Argo Rollouts and Aikido remain unverified.
8. Ping via the private copy goes stale on package updates; re-stage on update.
